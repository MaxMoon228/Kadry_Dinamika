### Ключевые факты из Приложения 1

- Данные ДОНМ (Москва) за **2022–2024** гг.; таблицы «Учителя», «Образование», «Повышение квалификации», «Школы».
- «Предмет» и «Параллель» указаны для одной пары: при нескольких предметах или параллелях **строки учителя дублируются**.
- «Тип образования» записывается **накопительным итогом**: запись 2022 г. повторяется в 2023 г.
- Школа идентифицируется **названием** (номер + юридический статус), явного school_id нет.
- Округ — **округ города**; муниципалитета/района нет.
- Target: 0 — остался в своей школе, 1 — перешёл в другую школу, 2 — ушёл из системы образования.
- В заголовке приложения упомянута «учебная нагрузка», но **полей нагрузки в таблицах нет** (нет часов и ставок). Нагрузка в интерфейсе не используется до подтверждения наличия поля.

## 4. Найденные проблемы

### 4.1 Архитектура
1. Страницы напрямую импортировали массивы `SCHOOLS` и `TEACHERS` и считали агрегаты на клиенте. Подключить API без переписывания UI было нельзя.
2. В `data.ts` смешаны генератор, справочники, domain-типы и бизнес-логика.
3. Нет асинхронности, а значит нет состояний loading, error и empty.
4. Роутинг жил в `useState`: URL не менялся, прямые ссылки и проверка доступа по URL были невозможны.
5. Фильтры категории, предмета, статуса, возраста и стажа в drawer показывались чипами, но **нигде не применялись**. Поля возраста и стажа были неконтролируемыми.
6. Реестр педагогов отдавал `slice(0, 60)` на клиенте, серверной пагинации не было.

### 4.2 Роли и доступ
7. Роль влияла только на текстовую подсказку. Директор видел все школы, все округа и всех педагогов.
8. `schoolById(id) || SCHOOLS[0]`: при неверном id молча открывалась чужая школа.

### 4.3 Синтетические допущения и некорректные показатели

| Было | Проблема | Стало |
|---|---|---|
| `School.avgAge`, `avgTenure`, `under35`, `senior` — случайные числа | Не выводились из педагогов | Считаются из срезов педагогов (derived) |
| `School.mobility[year]` — случайные доли | Не согласованы с педагогами | Строится ETL из присутствия педагога в срезах t и t+1 |
| Мобильность «за 2022/2023/2024» | При данных 2022–2024 исход наблюдается только для 2022→2023 и 2023→2024 | Периоды `t → t+1`; для 2022 показывается пояснение «исход не наблюдается» |
| Средний возраст системы = среднее средних по школам | Невзвешенно | Среднее по педагогам |
| Мобильность по округам = сумма долей школ | Математически некорректно | Считается по исходам педагогов |
| Dynamics: `shift = (yi-1)*1.5` и `base + yi*(i-2)` | Изменения по годам **выдуманы** | Структура по реальным срезам каждого года |
| Dynamics: «Средний пед. стаж 18.7» | Hardcode | Вычисляется |
| Overview: sparkline `[46.1, 46.4, avgAge]`, `[26,27,28]` | Hardcode | Тренд по срезам |
| Forecast: `Math.random()` в render | Случайный «прогноз» | ModelService, данные явно помечены mock |
| Forecast/Calculator: фиксированные важности и 56/17/27% | Фиктивные значения | ForecastService + объяснение по контракту SHAP |
| Калькулятор: `onChange={() => {}}` | Форма не работала | Контролируемая форма, валидация, async-запрос |
| Калькулятор: «Учащихся на педагога» вводится вручную | Derived-признак нельзя вводить отдельно (рассогласование) | Вычисляется; школьные признаки берутся из справочника |
| `CATEGORIES`: «Соответствие», «Без категории» | В источнике: «Высшая», «Первая», «Вторая» | Справочник из данных + «Без категории» для пустых |
| `EDU_TYPES`: «Высшее педагогическое/непедагогическое» | «Педагогичность» — не поле источника | «Высшее образование», «Среднее профессиональное», «Дополнительное профессиональное» |
| `eduQual`: «Бакалавр/Магистр/Специалист» | В источнике квалификация — «Учитель математики» | Как в источнике |
| `ACTIVITY`: «Коррекционное», «Профильное»… | В источнике направление — «Математика» | Как в источнике |
| Одна запись образования на педагога | Их может быть несколько | Массив `TeacherEducation[]` |
| Один предмет, `parallel: "5–11"` | Строка = предмет × параллель | `assignments: {subject, parallel}[]` |
| TeacherProfile: `i < 2 ? "Остался"` | Траектория выдумана | Траектория по срезам + исходы периодов |
| `UPDATED = "2024-11-18"` | Hardcode | Из метаданных датасета |
| Округа «Северный/Южный…» | Абстрактные | Mock использует округа Москвы (ЦАО, САО…), значения по-прежнему синтетические |

Показатели, которых нет в источниках и которые **не** добавлялись: зарплата, нагрузка в часах, ставки, удовлетворённость, выгорание, причины увольнения, KPI, дата найма, стаж в текущей школе, полная карьерная история.

### 4.4 Визуальная система
- Около 40 hardcoded hex-цветов в charts и pages (`#6b7180`, `#eef0f4`, `#14b8a6`…), тёмной темы не было.
- Статусы окрашены в green/orange/red. Лекция 3 прямо рекомендует избегать связки red/green из-за дальтонизма.

## 5. Что сделано

- Слои: `domain` → `data/contracts` (raw / normalized / dto / repositories) → `data/adapters` (ETL) → `data/selectors` → `data/mock`, `data/api` → `services` → `hooks` → `pages`/`components`.
- Все страницы получают данные через `useData()`, асинхронно, с состояниями loading, error, empty и loaded.
- RBAC и school scope: UX-guard в UI плюс имитация серверной проверки в mock (403 на чужую школу или педагога).
- Hash-роутер с URL для каждой страницы; глобальные фильтры (год, округ) хранятся в query-строке.
- Semantic tokens, светлая и тёмная тема (плюс System), палитра lavender/violet/indigo/blue. Статусы: синий, янтарный и розовый с иконками.
- ForecastService и ModelService (mock и API), журнал инференса, страница «Мониторинг модели» для аналитика.
- 34 unit-теста и 25 smoke-тестов маршрутов (vitest + jsdom); `build` теперь включает `tsc --noEmit`.
- `oxfmt` обновлён с 0.2.0 до 0.71: версия 0.2.0 при форматировании удаляла разделители членов type literal и скобки в типах вида `(A & B)[]`. Повреждения исправлены, typecheck и тесты пройдены повторно.
- Добавлен корневой ErrorBoundary.
- Документация в `docs/`.
